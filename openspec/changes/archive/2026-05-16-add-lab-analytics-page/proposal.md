## 为什么

产品已经有 `labResults` 数据结构和 `/record/:id` 里的基础实验室趋势表，但用户真正期待的是侧栏 `统计` 入口能进入一个独立的网页端统计页面。文件上传应该统一发生在 `/app` 输入区，统计页只负责把已保存的血常规、血生化、肿瘤标志物读数转成表格、折线图和监测提醒。

这个 change 的核心是把实验室趋势体验从本地 Excel 转到 Firefly-Isle 网页端：用户在 `/app` 上传或输入报告内容，保存到 Supabase 后，在深色临床控制塔界面里查看异常指标和肿瘤标志物上涨提醒；无真实输入时使用 `/analytics/demo` 查看演示统计页。

## 改什么

- 新增真正的 `统计 / 实验室趋势` 网页页面，替换当前侧栏里的 `敬请期待` 行为，并支持 `/analytics/:id` 与 `/analytics/demo`。
- 新增网页端实验室报告摄入边界：文件入口统一放在 `/app` 输入区，复用 OCR / 结构化提取边界，统计页不再承载上传表单。
- 新增 Supabase 实验室报告批次概念，让一次上传 / 一次检查报告可以拥有多条 `lab_results` 指标读数。
- 继续以 `lab_results` 作为单项指标读数的唯一事实源；趋势摘要、图表结果、监测判断不额外持久化成第二份事实。
- 在网页端渲染血常规、血生化、肿瘤标志物的趋势表格和单指标折线图。
- 用户选择某一个指标后，可以查看该指标随时间变化的数值、参考范围、最新值、读数数量和图表等价表格。
- 自动汇总：
  - 每个实验室分类最近一次检查中的异常指标；
  - 连续两次上涨超过 20% 的肿瘤标志物。
- 吸收本地 `update-followup-data` skill 里有价值的能力：固定指标字典、行映射、NLR / PLR / MLR 等血常规派生指标、参考范围解析、趋势监测规则。
- 本地 Excel 工作流只作为历史参考和映射来源；P0 产品体验不要求用户维护本地 Excel 图表或表格。
- 以这张生成图作为视觉方向：`/Users/Totoro/.codex/generated_images/019e17ab-72da-7e32-a189-25448263ad1e/ig_0432b0a4ec57ec2d016a02020e532c8191a59de7008f19beaa.png`。核心形态是深色临床控制塔：左侧指标索引、右侧图表 / 表格、底部监测面板。
- 所有监测输出都必须保持非诊断语气，不给诊断、进展结论、用药或治疗建议。

## 能力范围

### 新增能力

- `lab-report-ingestion`：通过 `/app` 输入区发起网页端上传、OCR、结构化提取、用户确认、保存到 Supabase 的实验室报告摄入流程。
- `lab-analytics-page`：独立统计页面，支持 `/analytics/:id` 真实记录、`/analytics/demo` 演示记录、分组浏览实验室趋势、网页端图表、最近异常汇总和肿瘤标志物上涨提醒。

### 修改能力

- `supabase-schema`：新增实验室报告批次存储，并扩展实验室读数元数据，支持网页端摄入、派生指标和来源追踪。
- `lab-result-trends`：把趋势分类从 `/record/:id` 的基础表格扩展到最近异常汇总和肿瘤标志物连续上涨检测。
- `app-shell`：当统计页面实现后，把侧栏 `统计` 的敬请期待动作替换为真实路由入口。

## 影响范围

- 前端路由和壳层导航：`src/routes`、`src/components/system/sidebar-nav.tsx`。
- 新增统计 UI 组件：位于 `src/components` 下的新 analytics 模块或等价目录。
- 实验室报告摄入流程：通过 `/app` 复用 `src/lib/medical-document-ocr.ts`、`src/lib/extraction.ts`，并保留实验室专用字典与批次持久化边界。
- 实验室趋势纯逻辑：扩展 `src/lib/lab-results.ts` 或新增同级纯逻辑模块。
- 患者记录持久化边界：`src/lib/patient-record-storage.ts`。
- Supabase 迁移：新增批次元数据，并扩展实验室读数元数据。
- 测试：覆盖解析、持久化、趋势分类、统计 UI 状态和路由。
- 本 proposal 阶段只更新产品 / 设计 / 规格文档，不包含运行时代码实现。
