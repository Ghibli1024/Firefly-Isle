## Context

顶栏“创作初衷”纸页同时拥有 Canvas 纹理、WebGL 阅读舞台、无 WebGL 降级和辅助技术文本四个呈现层。旧内容不适合公开发布，且曾经由静态预览、原生壳构建产物和 Git refs 传播。用户指定以一则公开 YouTube 社区帖子作为新页面内容来源。

## Goals / Non-Goals

**Goals:**

- 用单一内容模块提供用户指定公开帖的忠实段落整理、来源标签和规范化 URL。
- 让 WebGL、降级阅读页和屏幕阅读器都能访问同一份外链；外链必须在新标签页打开且不传递 referrer。
- 删除静态预览入口，并在可控 Git refs 中移除承载旧内容的路径与对象。
- 通过 Web 构建和 Capacitor sync 刷新 iOS/Android 打包资源。

**Non-Goals:**

- 不转载或镜像任何未明确指定为公开来源的外部内容；本变更只使用用户指定的公开 YouTube 帖子。
- 不修改用户的其他未提交登录、认证或 Demo 工作。
- 不承诺删除他人 clone、第三方缓存、已下载压缩包或平台服务商尚未执行物理清理的内部副本。

## Decisions

### 单一公开内容源

`origin-story-content.ts` 仅导出公开帖子段落、标题、副标题、来源标签和 URL。Canvas 与纸页组件都从它读取；不在视图层复制正文。这消除了多份正文漂移和重新引入非公开文本的风险。

替代方案是把链接只放在纸页组件中。该方案会让 Canvas、降级页和辅助文本的来源归属不一致，因此不采用。

### 结构化尾段样式而非文字匹配

Canvas 通过最后一个公开故事段落的索引决定强调样式，不再依据某一段字面值判断。内容更新因此不需要调整渲染逻辑，也不会把旧文本留作分支条件。

### 可点击 DOM 外链覆盖 Canvas

Canvas 本身不能安全地承载可访问超链接。因此 WebGL 舞台在画布上方放置来源链接；降级页使用同一个链接组件；隐藏的语义文章也包含链接。所有入口统一 `target="_blank"` 与 `rel="noreferrer"`。

### 历史净化与发布边界

在隔离镜像中用 `git-filter-repo` 删除旧路径，清理特殊 refs、reflog 和不可达对象，再将已验证 refs 用精确 lease 强制更新远端。不能用普通提交或 `.gitignore` 代替历史重写。

## Risks / Trade-offs

- [历史重写会改变 commit/tag OID] → 先保存 owner-only bundle，记录远端旧 OID，使用 `--force-with-lease`，并明确通知协作者重新 clone 或安全 reset。
- [GitHub Release 旧源码归档可能继续可访问] → 审计受影响 Release，删除或重建其发布记录，并按平台敏感数据清理流程申请缓存/对象 purge。
- [外部帖子未来删除或修改] → 页面保存用户指定公开帖的段落整理和原帖地址；外链失效不影响应用核心流程。
- [Capacitor 目录保留旧打包文本] → 在源码变更后执行构建和 `npx cap sync`，再扫描生成产物。

## Migration Plan

1. 在净化历史的隔离副本中恢复只含公开内容的纸页组件并删除静态预览入口。
2. 运行规格验证、单元测试、类型检查、lint、生产构建和 Capacitor sync；扫描工作树与对象数据库。
3. 精确更新受影响远端 branches/tags，并审计/处理受影响 GitHub Releases。
4. 将原始脏工作区切换到净化历史，再按备份恢复与本任务无关的暂存、未暂存和未跟踪改动。
5. 在成功验证后删除临时 bundle、补丁与隔离镜像；该删除仅覆盖本机可控文件。

## Open Questions

- GitHub 对已发布源码归档的敏感数据缓存清除是否需要 Support 工单，取决于 Release 删除后的实际可访问性；必须在远端 refs 更新后现场验证。
