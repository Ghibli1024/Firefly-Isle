## Context

顶栏“创作初衷”曾同时拥有 Canvas 纹理、WebGL 阅读舞台、无 WebGL 降级和辅助技术文本四个呈现层。旧内容不适合公开发布，且曾经由静态预览、原生壳构建产物和 Git refs 传播。用户已指定一则公开 YouTube 社区帖子作为新内容来源，并明确指出羊皮纸质感、WebGL 布料和尾段粗体与现有项目视觉格格不入。

项目正式生产视觉真源仍是 V3 Clinical Archive Console。创作初衷属于已登录工作区的系统弹层，应使用与病历页相同的 surface、边界、字体和动作语义，而不是维护独立材质系统。

## Goals / Non-Goals

**Goals:**

- 用单一内容模块提供用户指定公开帖的忠实段落整理、来源标签和规范化 URL，并将来源文本附在正文末尾。
- 用单一 DOM dialog 同构支持暗亮主题，消费 `--ff-surface-*`、`--ff-text-*`、`--ff-border-*`、字体和圆角 token。
- 不显示重复的可见主标题；以低调 mono 元数据、副标题、细橙色阅读轨和系统间距组织阅读层级。
- 保持全部故事段落为普通字重，包括最后一段；来源为正文末尾纯文本，不渲染 `<a>`、外链箭头或悬浮胶囊。
- 提供可见且可聚焦的关闭按钮，并保留 Esc、遮罩关闭、滚动锁定、Tab 焦点约束和关闭后焦点恢复。
- 删除静态预览入口，并在可控 Git refs 中移除承载旧内容的路径与对象。
- 通过 Web 构建和 Capacitor sync 刷新 iOS/Android 打包资源。

**Non-Goals:**

- 不转载或镜像任何未明确指定为公开来源的外部内容；本变更只使用用户指定的公开 YouTube 帖子。
- 不将 V4 评估 token 推广到正式路由；本弹层只消费 V3 生产视觉合同。
- 不修改用户的其他未提交登录、认证或 Demo 工作。
- 不承诺删除他人 clone、第三方缓存、已下载压缩包或平台服务商尚未执行物理清理的内部副本。

## Decisions

### 单一公开内容源

`origin-story-content.ts` 仅导出公开帖子段落、标题、副标题、来源标签和 URL。DOM 阅读弹层与测试都从它读取，不在视图层复制正文。这消除了多份正文漂移和重新引入非公开文本的风险。

替代方案是把来源地址只放在弹层组件中。该方案会让内容合同和展示层来源归属分离，因此不采用。

### 删除羊皮纸/WebGL 双路径

创作初衷是长正文阅读，不需要布料模拟、拖拽粒子约束、Canvas 字体绘制或 WebGL 能力探测。旧方案将同一内容拆成 WebGL、降级 DOM 和隐藏辅助文本三份呈现，并使用专属纸张色板，既增加维护分支，也违背 V3“长正文禁用干扰动效”和单一 WebGL 上下文原则。

新方案只保留一个语义化 DOM dialog。弹层使用系统面板、内嵌面、边界、文本和橙色强调 token；暗亮主题由根级 token 自然切换，不再写分支色值。移动端使用近全屏阅读面板，桌面限制阅读宽度和高度。

### 普通正文权重与统一来源

全部故事段落使用 UI 正文字体和普通字重。最后一段不再加粗，阅读收束通过段落节奏本身表达；细橙色左轨只建立模块层级，不把某句话塑造成宣传标语。来源标签与规范化 URL 合并为正文最后一个纯文本段落，之后仅保留低优先级医疗免责声明 footer。

### 系统级 dialog 交互

关闭按钮始终可见，使用标准 40px 方形点击区、1px 系统边界和橙色 focus ring。打开时锁定 body 滚动并把焦点移到关闭按钮；Tab 留在 dialog 内；Esc、点击遮罩或关闭按钮均退出，退出后焦点恢复到顶栏入口。动效只复用已有 `t-modal`，并自动服从 `prefers-reduced-motion`。

### 历史净化与发布边界

在隔离镜像中用 `git-filter-repo` 删除旧路径，清理特殊 refs、reflog 和不可达对象，再将已验证 refs 用精确 lease 强制更新远端。不能用普通提交或 `.gitignore` 代替历史重写。

## Risks / Trade-offs

- [删除 WebGL 后失去拖拽纸张效果] → 这是有意的复杂度删除；长文阅读获得更稳定的滚动、清晰文本、暗亮一致性和更低 GPU 成本。
- [历史重写会改变 commit/tag OID] → 先保存 owner-only bundle，记录远端旧 OID，使用 `--force-with-lease`，并明确通知协作者重新 clone 或安全 reset。
- [GitHub Release 旧源码归档可能继续可访问] → 审计受影响 Release，删除或重建其发布记录，并按平台敏感数据清理流程申请缓存/对象 purge。
- [外部帖子未来删除或修改] → 页面保存用户指定公开帖的段落整理和原帖地址；地址失效不影响应用核心流程。
- [Capacitor 目录保留旧打包文本] → 在源码变更后执行构建和 `npx cap sync`，再扫描生成产物。

## Migration Plan

1. 在净化历史的隔离副本中恢复只含公开内容的入口并删除静态预览。
2. 将创作初衷展示从 Canvas/WebGL 双路径迁移为 V3 token 化 DOM dialog，删除专属 Canvas 模块和性能预算测试。
3. 运行规格验证、单元测试、类型检查、lint、生产构建和 Capacitor sync；扫描工作树与对象数据库。
4. 精确更新受影响远端 branches/tags，并审计/处理受影响 GitHub Releases。
5. 将原始脏工作区切换到净化历史，再按备份恢复与本任务无关的暂存、未暂存和未跟踪改动。
6. 在成功验证后删除临时 bundle、补丁与隔离镜像；该删除仅覆盖本机可控文件。

## Open Questions
